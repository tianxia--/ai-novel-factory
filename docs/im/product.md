# 产品规格

本页为跨版本 IM 需求细节。产品定位、分版范围、实施与验收以[通用平台 PRD](../product/README.md)为准；小说只是一种独立能力，所有符合契约的能力都可按人物/工作组合。

项目边界更新：IM 与小说能力独立部署、存储、发布，通过插件组合，见[架构决定](../architecture/README.md)。本页定义产品行为；能力相关领域对象在各自服务管理，IM 只持有获准的外部引用。

## 1. 人物与现实映射

人物有长期 ID、姓名、头像、专业定位、人格版本、模型绑定、能力授权、知识库、联系人、群组、私聊、经历、私人资料和逻辑 Session。专业描述不产生权限；人设背景不冒充已经发生的经历。只根据真实收到的消息、真实执行的工具和实际产物记录事实。

人类用户和 AI 都是 Actor。系统所有者是管理身份，不是隐含加入全部会话的全知群成员。首版单所有者本地工作空间，代码仍显式带 workspaceId，测试跨空间拒绝；远程多用户不是默认上线能力。

## 3. 核心对象

| 对象 | 属于谁 | 生命周期与限制 |
| --- | --- | --- |
| Actor / Profile | 工作空间；AI 由所有者管理 | 创建、配置、暂停、启用、归档；不随小说删除 |
| Conversation | 参与者共享 | DM 或群；群归档不销毁人物 |
| Membership | 人物与会话之间 | 每次加入独立 epoch，历史边界不覆盖 |
| Message / Delivery | 消息归会话，收件状态归接收者 | 一条事实、多份收件；已发送不等于已处理 |
| WorkContext | 指定人物与用途/受众 | Task 可空；绑定本次能力/知识配置 |
| Request / Commitment / Task | 请求者、接受者分别记录 | 明确工作才使用；不能代另一人接受 |
| Capability / Grant | 定义可共享，授权按人/工作 | 工具执行、技能指南、账号引用与权限分开 |
| Knowledge / Resource | 私人、群、项目或工作 | 有所有者、版本、范围、用途、披露规则 |
| LogicalSession / HarnessSession | 人物的会话/工作上下文 | 映射不同版本与 epoch，不是人物本身 |
| Run / Effect | 一次执行与副作用 | 预算、租约、停止、未知效果核对 |
| Artifact / Review | 产物作者、审阅者 | 审阅只对指定版本生效 |
| Memory / Experience | 人物 | 从真实事件形成候选，授权后才跨任务复用 |

## 4. 主流程与例外

### 创建人物

填写姓名和专业定位，可进一步配置人格、模型、能力和知识库。先以 paused 保存；模型连通、授权、运行隔离与预算检查通过才可启用。失败保留档案并显示原因，不创建假经历。修改档案按版本提交，冲突时展示新版本而非覆盖。

### 单聊/私聊

从人物名录进入，重复打开复用同一 DM。你以自己的身份说话，AI 通过执行身份回复。AI 找另一位 AI 时同样创建/复用双方 DM；系统所有者只能通过独立观察入口看到。不能把人机私聊自动转发进群。

### 群协作

新建群、选择人物并发出邀请。邀请不等于已接受；群主能看到待接受状态。成员入群后按明确历史起点收件，需要旧信息时显式分享简报。群讨论先发生，分工可自然形成；协调人可选，不自带替别人接单或发布的权限。

@ 指定成员只决定应处理的收件，不提升权限。未点名时采用配置的回应策略；可以沉默，不要求每句话触发全员回复。成员可自己调用工具或转到私聊协商；公开群只接收获准的进展和成果。

### 工作配置

任务详情或会话的工作上下文抽屉分别设置执行人的能力、知识、账号与期限。有效长期授权加合法临时授权，再受本次选择和组织限制约束。变更默认下次运行生效；撤权立即阻断旧许可。完成工作不意味着永久获得那项能力或那套资料。

### 观察人物

显示该人的会话、群、联系人、工作、资料、记忆及 Session，常驻“正在观察”。默认没有发送框和写操作。读取不唤醒模型、不产生已读/处理回执，不把看到的信息再注入另一个人的上下文。

### 交付与停止

工具真正产生版本化成果后才显示交付。中断显示“停止中”，直到 Harness 与工具收束才显示“已停止”；外部效果不确定时“待核对”。恢复按授权和版本校验，不能重新公开已提交消息。

## 5. 小说能力包

| 人物常见定位 | 可单独挂载的能力 | 不自动获得 |
| --- | --- | --- |
| 编剧 | 构思、世界观、人物、剧情、章纲 | 正式 Canon 写回、发布权限 |
| 作者 | 写作、续写、修改、润色 | 其他项目资料、编辑验收权 |
| 编辑 | 审稿、节奏、设定一致性、修改建议 | 替作者承诺、静默改正文 |
| 统筹 | 组织讨论、分工建议、进度跟进 | 全知私聊、代人接单或审批 |

上述是模板而非写死角色。同一个人可获多项能力，多人可共享工具实现。旧质量规则、词汇资源、版本门禁留在领域工具内；旧 autopilot 和新执行者不能同时写同一个小说工作。

小说引擎作为独立能力服务保留自己的 API/CLI 和数据库。人物默认自己创作，再调用工具保存与检查；旧完整自动流水线作为可选批处理能力显式挂载，不自动替换群内人物的职责。

## 6. 不做的事情

首版不模拟生理需求、财产、住址；不默认自动安装模型提出的程序；不做多 Harness 热切换；不默认给 AI 管理全部人物的超级权限；不把社交关系模拟为已经发生的真实经历。附件、多模态、定时工作在核心 IM 和安全链路通过后分批实现，不用占位按钮假装可用。
