## 2. 本轮代码

新增 `src/collab/contracts.ts`、`schema.ts`、`store.ts` 与 `tests/collab.test.mjs`。现有 FactoryDb 只增加导入、缓存字段和 `getCollaborationStore()`，没有改 open/migrate/close 的实现或旧方法签名。仍使用同一个 factory.sqlite 和同一 SQLite 连接；未操作用户的生产数据库。

模块按需初始化，现有 server/worker 没有调用新入口。构建产物在本仓库是已跟踪文件，因此核心 build 同时产生相关 bundle 和类型文件变化；这些不是额外改造了旧生产逻辑。后续提交时应包含一致的生成产物，不提交半套 chunk 引用。

存储状态支持 paused AI，但本轮不启用任何模型。测试使用受信 principal 夹具模拟成员写入，不是允许 HTTP 客户端凭 ID 冒充人物。身份认证、成员启用门禁和运行凭证属于 D2/D3。

## 3. 已通过的 16 项

1. 新表按需创建，复用现有数据库，无小说项目依赖。
2. 工作空间初始化与人物创建幂等，新 AI 初始暂停。
3. 人物档案改名不换身份，版本冲突拒绝，私人指令不向无权成员开放。
4. 双向 DM 唯一，不同数据库连接重开也复用同一会话。
5. AI-AI DM 共享时间线，所有者普通视角和其他人物不可读。
6. 观察无写入/处理副作用，所有者不能切换 actorId 冒名发言。
7. 邀请不授予历史，接受后按新消息边界读取与收件。
8. 离群/重入保留 epoch；旧邀请不能接受新邀请，旧消息重试不能旁路历史边界。
9. 只有加入的群管理员可邀请，当前唯一管理员不能直接离群。
10. 消息、收件、幂等记录只提交一次，seq 和分页正确。
11. 人工注入收件写入失败，消息、序号和幂等凭证全部回滚。
12. 跨工作空间的对象、档案、会话和观察请求被拒绝。
13. 关闭重开数据库后身份、历史、收件和重试结果保持一致。
14. 空输入、超限分页、无效受邀者不留下半套数据。
15. 全部 8 个成员写命令在观察模式拒绝，人物、会话、成员、消息、收件和幂等表保持不变。
16. 数据库存在更高 IM schema 版本时拒绝初始化，不覆盖版本记录和已有消息。

这些是 store 集成测试，不等于 A01–A45 整套产品验收。真正多进程并发压力、网络故障、模型行为、工具执行、SSE 和浏览器测试仍未覆盖。
