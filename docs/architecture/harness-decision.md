# Harness 选型：复用 Pi，保留替换边界

日期：2026-10-20。结论：根据用户“复用合适的话 Pi 也行”的授权，结合独立 PM Bridge 的实际代码，选择复用 Pi 作为首版主 Harness。不是因为 OpenCode 不能实现，也不是把底座复用当成产品验收通过。版本范围与门槛仍由[产品 PRD](../product/README.md)决定。

开发目录更正：用户随后明确允许复制代码，但禁止修改参考项目。实施仅在 `projects/persona-im` 独立副本进行，原参考项目只读。下文的源码基线指已复制的实现，不授权在原项目继续开发。

## 1. 对产品的影响

人物身份、人格、私聊、群成员、消息、记忆、工作与权限属于平台；小说、代码、检索、数据分析等业务属于独立能力服务。Harness 只负责一次人物运行的模型调用、工具循环、事件和取消，不决定产品只能做什么业务。

因此，选择 Pi 不取消任何现有 PRD 要求，也不把人物变成编码助手。人物仍可以跨群、跨工作复用长期身份；不同会话/工作分别保存逻辑 Session 与授权。群是共同时间线，不是所有人共享同一个模型上下文。普通私聊不强制先建项目或工作。

Pi 的 Agent 核心提供状态、可自定义工具、流式事件、steering、follow-up 和取消/等待收束接口，足以承载这样的适配层；这些机制不是现成的多人物 IM、权限网关或可靠协作账本。[Pi Agent 官方接口](https://github.com/earendil-works/pi/blob/main/packages/agent/README.md)

## 2. 真实复用基线

独立 IM 宿主使用 `@earendil-works/pi-agent-core` 与 `pi-ai`，均固定为 1.2.0；不是反复运行 Pi CLI，也不是直接套用完整 coding-agent 默认配置。

| 模块 | 当前代码事实 | 本产品仍需做的工作 |
| --- | --- | --- |
| `packages/core/src/site.ts` | `SiteRuntime` 直接创建 `Agent`，注入人物、模型、工具和事件监听 | 收紧执行边界、完成状态与版本契约 |
| `storage/sites.ts`、`site.ts` | 宿主持久化 SQLite transcript/log 并重建运行；工作 Session 不同于聊天 Session | 兼容版本、恢复、取消与外部效果核对；不能当成已接 Pi 原生 JSONL SessionManager |
| `models.ts` | Provider/模型注册和选择；当前自定义接口适配为 Anthropic Messages、OpenAI Completions | 按实际模型验证工具、流式、错误和用量；不承诺任意 Provider 均兼容 |
| `plugin-tools.ts` | MCP 工具包装、每次调用重查人物权限、写入审批和审计 | 工作级工具/资源/账号范围、知识与披露 ACL、长操作账本 |
| `queue.ts`、`group-service.ts`、`peer-service.ts` | 人物工作队列、群路由、同事求助及部分循环限制 | 明确收件/承诺、单人写入、因果链预算、持久等待与恢复 |
| `sandbox.ts`、`runner.ts` | 本地命令和路径保护 | 不可信插件/扩展的进程隔离、网络与资源限制仍需专门验收 |

现有 `npm run check` 的 1,940 项测试通过，是宿主工程基线；不代表我们的 P01/P02 全部验收，更不等于已做真实模型及长稳测试。

## 3. Pi 与 OpenCode 的选择成本

| 考虑点 | 复用当前 Pi | 改用 OpenCode 主 Harness |
| --- | --- | --- |
| 接入形式 | Node SDK，已有宿主集成 | SDK 调用 headless 服务，需要服务监督和适配 |
| 自定义人物和动态工具 | 沿用当前人物/工具注入，增量收紧 | 需映射原生 Session、Agent 配置、工具和权限事件 |
| Session 与上下文 | 沿用当前宿主 SQLite，但承担兼容/恢复责任 | 映射逻辑 Session 到服务 Session，处理双侧状态与重连 |
| 多人物 IM/工作授权 | 都必须由我们实现 | 都必须由我们实现 |
| 本次迁移难度判断 | 较低：保留现有运行路径和测试，重点是补缺口 | 较高：替换当前 SiteRuntime 集成并回归上下游，不是换一个构造参数 |
| 主要取舍 | 嵌入进程控制直接，但需处理共同故障范围 | 多一个服务运维面；独立进程也不等于完整安全隔离 |

以上难度是根据当前代码的工程判断，不是普遍性能排名或完成工期承诺。OpenCode 官方 SDK 支持启动/连接服务并控制 Session；它仍是可行方案，只是当前宿主迁移成本更高。[OpenCode SDK](https://opencode.ai/docs/sdk/)、[Server](https://opencode.ai/docs/server/)

## 4. 不能原样照搬的行为

1. **权限默认值**：当前插件的只读工具可以默认授予所有人物。只读并不代表数据公开；按本产品的能力、资源、知识权限收紧，不能把“安装插件”当成“全员可读”。
2. **人物与模型**：无模型可保存暂停档案，启用有明确门槛。当前任务路径存在首个模型回退，另有默认模型重答；须按显式策略处理并记录实际执行配置，不能悄悄冒充人物自己的配置。
3. **并发与轮次**：宿主默认每人最多两个工作，不等于单人单写者。本产品要协调私聊/群工作和工具效果，服务端记录因果链、轮次与费用预算，不把 Pi 工具并行当成业务并行许可。
4. **停止**：发出 abort 只是取消请求。进入 stopping，等待模型和工具收束或确认超时，才结束运行；已经提交的外部效果不能声称被 abort 回滚。
5. **恢复**：宿主中断工作会换新尝试运行，不继续半截工具调用。这不保证外部动作只发生一次；需要幂等键、operation 账本和未知效果核对，不能盲目重放。
6. **隔离与凭据**：应用层权限、独立目录或独立 Agent 对象都不是进程安全边界。凭据留在可信网关，不交给模型；对不可信能力进程限制文件、网络和凭据范围。Pi 官方也明确需要 OS/容器/VM 等边界，项目 trust 不能替代隔离。[Pi 安全说明](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/security.md)
7. **升级兼容**：固定当前依赖和锁文件，升级前验证事件收束、工具结果、transcript、压缩和重启。线上旧 Session 带格式/适配版本，不能认为内部消息结构永久不变。

## 5. 架构约束

`IM 与人物领域 → 运行控制层 → Pi 适配 → Provider`；工具经可信能力网关调用独立 MCP 服务，知识也经工作授权检索。

运行控制层使用通用人物 ID、逻辑 Session、Run、上下文版本和运行事件。Pi 类型与事件转换限制在运行模块；前端协议、能力契约和小说服务不导入 Pi 类型。沿用现有 `SiteRuntime` 作为实施入口，不另外手写模型/工具循环，也不提前造一套没有调用者的双 Harness 框架。

需要明确的控制语义为创建/恢复、投递、插话、停止并等待收束、订阅及只读快照。创建运行时冻结本次模型、人格、工具、知识和授权版本；撤权在新调用时重新校验，必要时停旧运行、重建获准上下文。具体 API 和迁移随对应 PRD 实施，不把这里的接口描述当成已实现代码。

持久的逻辑会话与模型原生上下文分离。未来换 Harness 可以保留人物与 IM 历史，但原生隐藏状态、token 缓存和中途工具调用不承诺无损迁移；在空闲边界停止旧运行，以可追溯消息/摘要创建新绑定。

## 6. 后续 OpenCode 的位置

首版只维护一个主运行路径。如果以后需要专门的编程代理，可以先把 OpenCode 接成独立“编程能力服务”：人物通过授权 MCP 连接器使用它，能力服务用自己的 SDK/Session 和工作目录执行。它不是替代作者、研究员等人物身份，也不要求 IM 内核改成编程工作流。

这只是保留可选路线，不新增本版必做能力，也不承诺自动具备编程服务。只有出现明确需求与验收收益时，才新增对应能力 PRD，或正式评估更换主 Harness。

## 7. 分版落实

- v0.1：人物档案/版本与启用门槛、私聊/群/观察、独立 Session、单人停止、收件幂等和通信预算；真实模型单列授权验证。
- v0.2：兼容能力发现、按人物/工作授权、知识与披露边界、长操作/未知效果核对；验证检索和数据分析两类非小说任务。
- v0.3：显式协作、等待、写入并发与 fencing、恢复、版本审阅和可追溯记忆。
- v1.0：升级/备份恢复、权限回归、支持矩阵、性能、长稳和用户验收。

不因选择 Pi 降低任何验收要求。若停止/恢复/权限等门槛未通过，修复或重新选型，不用框架名声替代实测。
