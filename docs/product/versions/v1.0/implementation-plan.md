# v1.0 实施计划

状态：planned。依据 [PRD](prd.md)，验证以[P10 清单](acceptance.md)为准。

| 实施项 | 对应需求 | 交付与依赖 | 验证方式 |
| --- | --- | --- | --- |
| P10-T01 产物与支持矩阵 | P10-R01 | 锁定宿主、平台/架构、依赖和模型/插件兼容，打包/启动诊断 | 干净安装环境，不带开发源码目录 |
| P10-T02 数据恢复 | P10-R02、P10-R03 | IM 与能力各自备份、引用清单、迁移/升级预检、兼容回退 | 备份恢复演练、未知版本拒绝、未决操作恢复 |
| P10-T03 权限回归 | P10-R04 | 聚合各版负向/撤权、凭据与观察测试，修复边界差异 | canary、真实网关/提供方拒绝、诊断脱敏 |
| P10-T04 稳定与性能 | P10-R05、P10-R06 | 固定数据/硬件、稳定性运行、故障/乱序/重启，界面与查询性能收敛 | 8 小时/200 操作/重启组合、30 样本 p95、多宽度截图 |
| P10-T05 诊断与用量 | P10-R07 | 日志关联、用量/额度、错误/恢复入口、可控导出 | 密钥/私聊 canary 不泄漏；账本可核对 |
| P10-T06 发布验收 | P10-R01、P10-R02、P10-R03、P10-R04、P10-R05、P10-R06、P10-R07、P10-R08 | 全需求/缺陷/用例追踪、工程报告、用户体验与发布说明 | P01/P02/P03/P10 实际构建验收，用户独立结论 |

先锁定支持矩阵与数据恢复，再做长时间稳定性和性能，最终形成发布候选。测试出新缺陷则修复并执行相关回归，不为减少时间跳过长期用例。

## 发布与回退

每次发布候选关联 commit/build、PRD 修订、数据 schema、Harness/插件/服务/契约矩阵、依赖锁与完整验收报告。公开报告脱敏，原始敏感证据受控访问。

升级失败不写未知 schema，不自动安装不兼容插件。回退根据备份和兼容矩阵执行；已提交第三方动作依事实核对。正式发布前的用户验收尚未发生，模板不能当作接受记录。
