# v0.1 PRD：独立人物 IM

日期：2026-10-20。状态：implementing。父级：[产品 PRD](../../README.md)。需求共 10 项，均为本版 must；对应 [P01 验收](acceptance.md)。

## 1. 目标与范围

用户可以打开一个独立 IM，创建有姓名/人格/专业定位的 AI 人物，配置模型，进行真实私聊和群聊，观察人物自己的会话世界。没有任何小说项目或外部业务能力也能使用。

首版本地单所有者。专业定位只影响人格说明；外部工具安装与任务级知识在 v0.2，正式请求/承诺/任务依赖在 v0.3。v0.1 内部通信工具只处理发言/收件，不借此开放文件或业务系统。

## 2. 用户流程

首次进入 → 创建人物 → 可先保存暂停档案 → 配置有效模型 → 启用 → 从名录进入私聊 → 收到真实回复。创建第二个人 → 建群并邀请 → 接受后加入 → @ 指定成员讨论 → 查看各自署名消息。

人物需要联系同事时创建/复用双方 DM；其他人不自动看到。所有者从人物选择器进入只读观察，查看该人的私聊、群和已存在 Session，再返回自己的视角。观察不等于以该人身份操作。

## 3. 页面与状态

消息列表、私聊/群聊、联系人、人物详情/创建、群创建/邀请、模型设置、只读观察是本版页面。人物已有工作/记忆等栏目仅显示真实可用记录；尚未交付的操作不显示为可点击成功功能。

页面具备初始空、加载、发送中、失败重试、离线、暂停、待邀请和只读状态。发送失败保留正文与 requestId；中文输入法 composition 中 Enter 不发送。慢请求和观察切换的迟到响应不能覆盖新视角。

## 5. 权限、数据与运行

所有者认证产生可信用户上下文；人物运行产生受限执行上下文。观察凭据不成为人物写凭据。IM 消息与模型 Session 分开保存；收到消息不表示处理完成。群重入使用新 epoch，旧 requestId 不能旁路新历史边界。

一个人的不同会话保留独立逻辑 Session；模型或人格修改保持人物 ID，运行按明确版本开始。预算和计数由服务记录，不依赖模型自述。首版同一人物默认最多一个有写效果的运行，其他请求排队。

## 6. 非功能与门槛

只读观察/重试/越权测试须使用真实后端，真实回复须至少演示两个人各自独立运行。确定性模型替身可覆盖故障和预算，验收报告单列一次已授权的真实模型验证及调用费用；没有运行条件则记 blocked。

UI 覆盖 320/390/900/1440px、200% 缩放、长姓名和长消息；正文与操作不遮挡，主要按钮触摸区域至少 44px。断线恢复之后以服务端消息 ID 去重，不显示两条同一次发送。

P01-A01–P01-A10 全部通过，关联回归通过、阻断缺陷为零后进入工程验收；用户对具体构建接受后才记录 user_accepted。已有 PM Bridge 或局部存储测试不自动满足本版要求。
