# v0.1 实施计划

状态：implementing。依据 [PRD](prd.md)，验证以[验收清单](acceptance.md)为准。已按用户授权把参考代码复制到独立 `projects/persona-im`，只在副本继续开发。人物观察已迁入；其余必需项仍按下表推进，整版未验收。

## 1. 实施项与顺序

| 实施项 | 对应需求 | 交付与依赖 | 验证方式 |
| --- | --- | --- | --- |
| P01-T01 宿主与边界 | P01-R10 | 对 PM Bridge 的启动、数据、Pi、UI、许可证与现有能力做可重复评估；形成宿主 ADR 与构建基线；平台源码/文档落到独立 IM 仓库 | 没有小说 checkout/进程的独立构建/启动；记录尚缺差异 |
| P01-T02 人物与模型 | P01-R01、P01-R02 | 可信 owner、人物 CRUD/版本、模型/密钥配置、启用门槛；复用宿主实现并补行为差异 | 档案版本、密钥不回显、无模型暂停、真实连接失败 |
| P01-T03 IM 持久域 | P01-R03、P01-R04、P01-R06 | DM 唯一、成员 epoch、邀请、消息/收件/去重、分页；迁入有价值测试，不保留平行第二套生产聊天模型 | 真实数据库正反用例、重启、故障回滚 |

T01 完成后才能确定在哪个宿主模块实施；T02/T03 支撑 T04/T05，T06 在真实 API 上贯通，T07 在具体构建上执行。无需等待小说生产回归修复才能推进。

## 2. 接口与数据

IM 自有 actor/conversation/membership/message/delivery/session/run 等记录；具体复用宿主已有表时在 ADR 中说明映射。保留外部资源可扩展接口，字段不要求 novelId、chapterId 或业务 projectId。

现有 FactoryDb 中的 collab 入口暂保留作旧原型记录，IM 不以它作为生产存储。真实数据迁移单独设计保留 ID、成员历史和幂等关系；没有数据证据不执行自动搬迁。

## 3. 交付与回退

测试只操作隔离数据目录。升级前备份 IM 自己的数据，失败可回到对应兼容构建；不通过删除聊天数据解决问题。身份和消息权限等 must 缺陷阻断本版，不能靠关闭观察或群入口称为通过。

验收记录列出源码/构建、Harness/模型、测试数据、结果和遗留项。用户验收前保持 engineering_verified 或更早状态，不能由开发者代签。
