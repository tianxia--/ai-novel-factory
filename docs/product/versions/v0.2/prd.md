# v0.2 PRD：通用能力与知识挂载

日期：2026-10-20。状态：planned。依赖 v0.1 已验收行为。需求共 10 项，均为 must；对应 [P02 验收](acceptance.md)。

## 1. 用户结果

用户给同一个人物挂载符合契约的不同能力，然后在私聊/群里提出需求，该人物使用实际工具完成工作。平台不限制业务类别，配置不足时明确指出缺项。

本版首先验收资料检索和结构化数据分析两类能力；小说可以独立接入，不作为平台必装功能或验收依赖。正式多人承诺和复杂等待图放 v0.3，单人执行和已有群通信保留。

## 2. 主流程与页面

能力库 → 安装/连接 → 查看真实工具与技能 → 给人物授权 → 私聊/群提出需求 → 选择或复用本次工作上下文 → 指定资源/知识/账号 → 确认有必要的动作 → 人物调用 → 查看进度、结果或失败 → 继续沟通。

用户可以在创建人物时选择已安装能力，也可随时为已有的人物增减能力。已配置且范围不变的调用无需重复选择。能力详情区分安装、连接、授权与生效状态；工作抽屉区分长期项、临时项、未选择项和缺少配置。

结果使用通用文本/文件/表格/版本卡，包含实际执行人和资源来源。领域专用 UI 属于插件扩展。卸载能力之后保留对话和历史引用，对无法再访问的资源明确标记。

## 4. 生效规则与异常

能力可执行须同时满足已连接/兼容、人物资格或临时授权、工作选择、当前审批和提供方资源权限。模型自称“我擅长”不产生权限。新授权/工具集默认下一次运行生效，撤权立即生效。

模型窗口/格式不支持某能力输入时先拒绝该操作并显示原因，不能静默忽略附件或资料。资料索引失败保留来源和可重试状态；连接测试与真实任务都记录使用量，不保证任何模型对任何领域必定成功。

网络超时以原 invocation 查询，不创建新效果；取消若与提交竞争，以真实提交状态显示，未知先待核对。公开结果由当前披露权限决定，工具原始结果不自动发给全群。

## 5. 非功能与发布门槛

通用能力、授权、知识和 operation 遵循[能力契约](../../../architecture/capability-contract.md)。独立服务/插件各自构建，不共享 IM 私有表或源码。外部工具文本视为资料，不直接改网关权限。

两类验收任务分别使用一组可核对文档和一份固定 CSV；最终引用来自获准文档，统计与程序计算一致。夹具通过和真实模型工具调用分别保存证据，缺少任一项不能以固定结果代替。

P02 全清单、P01 回归与零阻断缺陷满足后才进入用户验收。通用字段、页面和安装流程不得要求创建小说/章节。
