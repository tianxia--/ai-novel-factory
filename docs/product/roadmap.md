# 版本路线、范围与追踪

日期：2026-10-20。各版本为完整规划稿，实际状态见 [releases.json](releases.json)。不以历史存储测试数量推算产品完成比例。

此处平台版本是本次 PRD 的交付编号。现有 PM Bridge/小说包各自的版本号不表示已经通过本 PRD 的同号版本验收。

## 1. 平台交付顺序

| 版本 | 用户能完成什么 | 依赖 | 明确后置 |
| --- | --- | --- | --- |
| v0.1 | 建人物、配置模型、真实私聊/群聊、同事私聊、观察人物、暂停和重启 | 独立 IM 宿主、身份与运行模型 | 外部业务插件、完整正式任务/承诺系统 |
| v0.2 | 安装任意兼容能力，按人/工作挂载，选择知识，直接发需求取得真实成果 | v0.1、能力网关与外部契约 | 复杂多人任务依赖、计划自动拆解、长期经验整理 |
| v0.3 | 多人接受/拒绝/求助、并行和交接、等待与恢复、版本审阅、可追溯记忆 | v0.2、持久工作与效果记录 | 多用户组织、跨设备同步 |
| v1.0 | 持续使用、升级/回退、备份恢复、可靠诊断与可重复发布 | 前三版工程与用户验收 | 云端团队、多租户、移动原生客户端另立 PRD |

v0.2 首先以“资料检索”和“结构化数据分析”两类无小说依赖的能力完成共同验收。两者使用隔离测试资料：前者检索/引用已授权文档，后者读取指定 CSV、计算可核对统计并产出报告。夹具/替身证明协议，真实端到端结果证明集成，分别记录，不能用固定回复替代人物执行。

以后新增能力可能需要自己的账号或专用 UI，但通用安装、授权、调用、结果和故障状态不修改 IM 核心。特殊展示通过插件扩展承载。

## 3. 小说及其他能力项目

| 独立能力版本 | PRD 范围 | 现有设计来源 | 平台前提 |
| --- | --- | --- | --- |
| 小说适配器 n0.1 | 项目只读、上下文只读、正文候选提交、操作查询/取消 | [n0.1 完整 PRD](capabilities/novel/n0.1/prd.md)与小说 S1/S2 | 服务可先独立开发；组合需平台 v0.2 契约 |
| 小说适配器 n0.2 | 故事/章纲提案、修改、审稿、指定版本提升 | 小说 S3/S4 和领域质量要求 | 使用 v0.2 通用调用；多人复杂协作依赖 v0.3 |
| 小说适配器 n1.0 | 完整领域验收、原有生产回归分类/解决、独立发布 | SEP 与领域正式验收 | 不要求平台和插件同时升至 1.0 |
| 其他能力 | 每个能力单独建立目标、权限、依赖、工具契约和用例 | 复用通用能力接入流程 | 符合平台支持的契约版本 |

此表是能力路线，不能替代各插件自己的 PRD。n0.1 已形成独立 PRD/实施/验收清单，尚未实现或验收；n0.2/n1.0 仍为路线意向。进入实现前，每个能力版本必须有已编号需求、用户流程、实施项与验收用例。

## 4. 版本兼容与计划变更

每个发布记录锁定 IM commit/build、Harness/模型配置、插件和服务版本、契约范围、数据 schema 与测试环境。模型密钥和私聊正文不进公开报告。

兼容性变更通过新契约主版本或明确适配发布；插件可独立升级和回退。平台默认不强制安装小说插件、不依赖小说的发布节奏，也不因小说既有回归失败冻结通用 IM 开发。

范围调整记录需求 ID、原因、用户影响、替代流程、用例和版本差异。未完成的 must 项导致该版本不通过；确需改范围时先修订 PRD 并记录确认，不能在验收时删除失败项。
