# OpenCode IM 接入验证与首版决定

- 更新：2026-10-15。
- 决定：首版使用 OpenCode 服务式 Harness；人物、IM、能力授权、知识库和调度由本应用管理。Pi 保留后续替换选项，当前不并行实现。
- 状态：本地确定性接入验证通过；不是生产准入，也不是完整 IM 已实现。
- 代码：[PoC 说明](../../scripts/opencode-im-poc/README.md)、[集成测试](../../scripts/opencode-im-poc/acceptance.test.mjs)。

## 接入方式

进程管理用 `opencode serve` 启动 headless 服务；本轮验证直接调用 HTTP API，不解析 CLI 输出，不通过反复执行 `opencode run` 驱动聊天。正式 worker 内的 `OpenCodeHarnessAdapter` 计划使用与发行版本匹配的 `@opencode-ai/sdk` 访问私有服务；SDK 是 HTTP 客户端，不是将 OpenCode 核心执行循环嵌入应用进程。[官方 SDK](https://opencode.ai/docs/sdk/)、[官方 Server](https://opencode.ai/docs/server/)

自有界面只访问业务 API，不直接得到 OpenCode 管理端点或凭据。人物互相发送 IM 消息，不通过创建临时 subagent 冒充同事。知识检索和领域工具经受限工具网关/MCP 提供，权威业务状态仍属于应用。

## 已验证

环境：macOS arm64、Node 24.10.0、已安装的 OpenCode 1.14.33。三个受控实例分别使用临时 HOME/XDG 数据目录、独立口令与个人模型配置。两组自定义 OpenAI-compatible Provider ID 均指向同一个本地替身服务，不能据此宣称已覆盖两家真实供应商或两种协议。

| 场景 | 实际断言 |
| --- | --- |
| 三位成员群聊 | 独立原生 Session，无同事父子 Session；实际模型工具循环发送三条署名消息 |
| 模型与工具分离 | 请求送达各自 Provider 路径和模型；只有作者请求中出现写作工具 |
| 独立写作能力 | 作者调用 MCP 写稿，测试网关产生归属于作者的成果 |
| AI 双向私聊 | 作者与编剧各自使用 DM Session；编辑输入及作者群 Session 不含私聊 canary |
| 网关负向校验 | 拒绝编辑访问私聊、越权写稿及伪造发言人 |
| 只读观察 | 获取成员视图和 Session 历史不增加模型请求或改变业务消息 |
| 单人停止 | 作者请求保持进行中时编辑可完成；abort 后作者到 Provider 的连接关闭并回到空闲 |
| 重启续接 | 作者 Harness 正常终止并重启，DM 历史保持一致，继续输入可完成 |

测试命令见 PoC 说明。8 个子场景全部通过，Node runner 连同外层测试显示 9/9；一轮产生 17 次本地替身请求，没有调用真实付费模型。讨论内容与工具选择是测试脚本指定的，不是三个真实模型自行达成分工。

本地接口差异：该二进制 `/doc` 返回的路径只有 `/auth/{providerID}` 与 `/log`，不能当作完整 Session 契约；已对实际 `/session`、消息、异步输入、abort、状态和历史接口进行调用验证。同步消息接口返回最终 assistant 消息，中间工具记录需从 Session 历史按 parentID 找回。生产 SDK 接入前要补版本匹配与类型契约测试，不能直接复用仓库现有旧插件 SDK 版本。

## 未验证

1. 真实模型的稳定人格、自然协商、自主选择工具、非编码写作质量、多供应商协议差异。
2. 任务级临时能力和知识库授权、检索 ACL、跨任务缓存与摘要隔离、撤权重建。详见[详细设计第 21 节](2026-10-14-person-world-detailed-design.md#21-按工作挂载能力与知识库)。
3. 容器/VM 文件与网络隔离，模型或工具恶意行为。独立目录/Session/权限配置不是安全沙箱。[官方安全边界](https://github.com/anomalyco/opencode/blob/dev/SECURITY.md)
4. 正在执行的外部工具能否终止、未知效果对账、强制崩溃恢复、持久收件/outbox、租约与幂等。正常重启保留聊天历史不等于故障后不会重复发言。
5. SSE 断线续接、压缩后来源保留、性能/费用、真实 IM 界面、完整 A01–A45 验收矩阵。

## 下一步

先落实身份和工作上下文、受限工具/知识网关、持久 IM 与 Session 映射，再接正式 SDK 适配器和消息界面。下一组专项验证包括：同一人物两项工作挂载不同能力/知识库；同一工具在不同工作中使用不同凭据/资料范围；撤权后旧运行、旧检索缓存和旧 Session 均不能继续读取。小说生产能力最后作为独立能力包接入，不恢复固定多人流水线。

本次不改生产引擎、worker、前端或 factory DB，也未执行生产全量回归。GitNexus 已刷新并调用影响查询，但新增 `.mjs` 符号未被查询解析，不能宣称取得其完整调用图；通过导入搜索及变更清单补查，生产代码没有引用这组独立脚本。通过本地 MCP 后端执行 `detect_changes(scope=all)`，结果仅覆盖已跟踪的两份索引统计文档，受影响流程为 0、风险 low；新脚本和方案仍未跟踪，另行人工核对，不能把该结果算作覆盖全部新增文件。未提交或推送。
