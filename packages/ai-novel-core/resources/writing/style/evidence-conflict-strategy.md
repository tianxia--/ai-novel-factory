# 多源事实冲突处理策略 (Evidence Conflict Resolution Strategy)

在长篇小说的长周期自动生产中，由于向量检索召回偏置、历史事实堆叠或不同模块的局部修改，可能会出现数据包内的信息相互冲突。模型必须严格遵循本策略进行冲突化解与优先级取舍：

## 1. 冲突解决优先级堆栈 (Priority Stack)

当不同信息源提供的设定或事实发生冲突时，模型必须按照以下权重链由高到低进行决策（高优先级直接覆盖低优先级）：

1.  **层级 1 (最高)：`working_memory` (当前章节即时指令 / 纠偏要求)**
    *   用户在本轮中显式输入的强制要求，或最近一次 Gate 质量报告中的返工修正命令。这具有最高的统治力。
2.  **层级 2：`blueprint` / `scene_brief` (章节蓝图与大纲目标)**
    *   本章大纲所规划的剧情节点、走向和核心动机。
3.  **层级 3：`character_dossiers` / `cards` (角色档案与核心设定卡)**
    *   系统记录的各角色言行标志、能力边界、人物欲望等固有常态属性。
4.  **层级 4 (最低)：`facts` / `summaries` (历史事实库与前序章节摘要)**
    *   通过 RAG 检索回来的远端片段或过往摘要。如果历史事实与当章即时指令或大纲有出入，以当章大纲及即时指令为准。

## 2. 无法调和的冲突处理机制 (Conflict Bypass Mechanism)

*   **避免在正文中裁决**：如果两个冲突的信息处于同一优先级层级，且模型无法推导其正确性，模型**绝对不允许在正文中给出强烈的确定性断言**。
*   **模糊性带过**：遇到此类冲突，模型应使用叙事模糊化手段带过，使正文逻辑保持双向兼容。
    *   *错误写法*：“他确信那是李四在三年前送他的玉佩（与另一处写两年前冲突）。”
    *   *正确写法*：“那枚斑驳的玉佩静静躺在桌上，承载着他与李四多年前的交情，岁月的痕迹已有些模糊不清。”
*   **禁止硬性因果链**：不得在发生信息矛盾的两个角色或事件之间擅自建立硬性因果锁链。
